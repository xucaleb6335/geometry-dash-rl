How this agent decides

Every 4 physics ticks (60 times a second) the bridge mod inside Geometry Dash reports the player (height, speed, game mode, gravity) and the objects near it: blocks, spikes, portals. That report is what the Game panel draws.

An encoder turns the report into a fixed list of numbers, the features, all measured from the player, so the same situation looks the same anywhere in the level.

The features feed two hidden layers of 128 neurons. Each neuron adds up its inputs times learned weights, plus a bias, and squashes the sum with tanh into [−1, 1].

Two outputs, Release and Jump, go through a softmax to give p(jump); the agent holds the button for the next 4 ticks when p(jump) is over 50%. A separate critic network of the same shape estimates the value V(s), the reward still to come; it only matters during training.

Reading the picture

  • Colours. Orange is negative, blue is positive, grey is zero, for features, neuron activations and connections alike (the TensorFlow Playground convention). A connection is drawn as its input × weight: its colour is the sign, its width the size, so it shows what actually reaches the next neuron at this moment.
  • Neurons are sorted by how they vote: the top rows of each hidden layer push toward Release and the bottom rows toward Jump while they are positive (blue), and the other way while negative (orange). Hover one for its inputs; click it to pin it and plot it under the run.
  • Game panel. Numbered outlines are the objects in the encoder's slots (obstacles first, then nearest). The faint columns ahead of the player are the terrain profile: floor height, spikes on it, room overhead. Dimmed objects are known from other frames but not in this frame's report. Portals the bridge does not report are marked where the mode changed.
  • Timing code. The distance to an object's left edge is also given as a row of bumps that slides left as the object approaches: the precise timing signal a small network needs.
  • Knock-out test. The Decision panel reruns the network with one input group set to zero, as if that object or signal were absent, and shows how p(jump) moves. It is a what-if, not the training signal.
  • Caveat. These policies are PPO plus behaviour cloning of checkpoint-search routes; on the hard levels they reproduce a learned route rather than react to unseen levels.
